SECTION 1

What an LLM call is

Explain like I'm 10

An LLM is a super-autocomplete. It reads your words as small pieces called tokens and guesses the next piece, then the next, until the answer is done. It forgets everything the moment it finishes.

Every LLM feature, however clever it looks, is one request: a list of messages goes in, one message comes out. The system message sets the rules. The user message carries the task, such as "summarize this invoice". The reply comes back with a token count and a finish_reason that says whether the model finished or was cut off.

The notebook first makes this call the raw way, naming one vendor's model inside the code. Notice what's missing: there's no cost figure and no limit, and switching vendor means editing code.

SECTION 2

Why a gateway

Explain like I'm 10

A universal TV remote. One remote works every brand of TV, and only the remote knows the passwords. You press "fast" or "smart"; the remote decides which TV to switch on.

Picture three teams each calling vendors directly. Each team holds vendor keys, nobody sees total spend, and if a key leaks you hunt for it across every codebase. An AI gateway is the one place every request goes through. DocuMind uses LiteLLM, which speaks one format to every vendor.

ConcernDirect to vendorThrough the gateway
Model namesScattered through codeAliases like fast and smart, in one config file
Switching vendorCode change everywhereEdit one line of config
Cost per callNot visibleReturned with every answer
Spend controlA bill at month endA cap, checked before each call
Approved modelsAnything goesOnly the listed aliases work
Retries, fallbacksRewritten in each appConfigured once (Module 04)

Library or server? In this course LiteLLM runs as a library inside DocuMind, so there is nothing to install or keep running. In a company, the same LiteLLM usually runs as a shared server that every team calls. The concepts are identical; only where it runs changes.

At enterprise scale

In a bank, the gateway is a shared platform service, and these are the questions to ask of it:

  • Secrets: vendor keys live in a secrets manager (for example HashiCorp Vault or AWS Secrets Manager), are injected at deploy, and rotate without any app noticing.
  • Identity: apps authenticate with SSO or service identities, and each gets its own virtual key per environment (Section 6).
  • Chargeback: spend per key and per team feeds finance; budgets and requests-per-minute limits are set per team.
  • Policy: an approved-model list per data classification, data-residency and retention terms per vendor, and an audit log of every call.
  • Resilience: several gateway replicas behind a load balancer. The gateway is now on the critical path, so it needs an SLO.
SECTION 3

Meet the gateway: aliases

The gateway's behaviour lives in app/config/settings.yaml. Its heart is the alias table: the only model names DocuMind may ask for, and the real model behind each one.

Alias the app usesReal model$ / 1M input$ / 1M output
fast → fast-anthropicClaude Haiku 5.50.100.50
smart → smart-anthropicClaude Sonnet 5.52.0010.00
fast-openaiGPT-6 Luna0.100.50
smart-openaiGPT-6.1 Sol2.0010.00

Prices are from LiteLLM's built-in price list as of November 2026. Vendors change them.

# app/config/settings.yaml (excerpt)
gateway:
  aliases:
    fast-anthropic: anthropic/claude-haiku-5-5   # alias → real model
    fast-openai: openai/gpt-6-luna
  shortcuts:
    fast: fast-anthropic                         # what feature code asks for
  num_retries: 2
  max_spend_usd: 1.00                            # per session (Section 6)

SECTION 5

Tokens, cost and knobs

Tokens are the unit of cost. English text averages about four characters per token. Output tokens cost about five times as much as input tokens, so long answers are the expensive part. Current models also think before answering, and thinking tokens are billed as output and count toward the output limit.

A worked example

Summarize INV-1001Tokensfast (Haiku 5.5)smart (Sonnet 5.5)
Input: prompt + invoice≈ 420$0.000042$0.000840
Output: thinking + summary≈ 300$0.000150$0.003000
One invoice$0.00019$0.0038
10,000 invoices / month$1.92$38.40

The same job costs 20 times more on the smart model. The notebook repeats this sum with your real token counts. Choosing the right model per task is model routing, the subject of Module 04.

The same question, different answers

The model picks each next token with some randomness, so the same prompt can give different wording on each run. Older tutorials set temperature=0 to reduce this. Current Claude models no longer accept temperature, and the notebook shows the rejection. You get consistency from clear prompts and structured output (Module 02), and you prove it with evals (Module 09), not with a knob.

SECTION 6

Spend caps

Explain like I'm 10

Pocket money. When it's spent, it's spent, however many times you ask.

In a company, the shared gateway's admin holds a master key and issues each app its own virtual key. A virtual key may use only certain aliases, has a budget, and can be revoked in seconds without touching any other app. Every request is checked against its budget before any vendor is called.

DocuMind keeps the same idea in miniature. A spend tracker adds up the cost of every call in the session and refuses the next call once max_spend_usd is reached. The unknown-alias check plays the part of a key's allowed-models list.

SECTION 7

The model has no memory

Tell the model a fact, then ask about it in a new request: it has no idea. Chat apps seem to remember only because they resend the whole conversation each turn. Memory is therefore paid for in input tokens on every message, and a long chat eventually overflows the context window, the most text a model can read at once.

Deciding what to send, and what to leave out, is context engineering (Module 08).

CHECKPOINT

Can you explain it?

Answer each question out loud before opening it. The same questions close the notebook.

A chat app "remembers" earlier messages. How, if the model is stateless?

The app resends the whole conversation with every request, so memory costs input tokens on every turn.

Name three things a gateway gives you that direct vendor calls don't.

Aliases (switch vendor by config), one format for all vendors, cost and latency per call, spend caps, an approved-model list, retries and fallbacks. Any three.

In a company, how is a spend cap usually enforced?

The shared gateway gives each app or team a virtual key with a budget, and checks it before calling the vendor.

The summary looks complete, but finish_reason is "length". What now?

It was cut off, and thinking tokens count toward the limit. Raise max_output_tokens or ask for less, and always check finish_reason.

A team wants to cut cost 20× on 10,000 invoices a month. What is your first question?

Does quality hold on the fast model? Answering that needs evals (Module 09), not a single test.

Glossary

token
A small piece of text (about four characters) that the model reads and writes; the unit of cost.
context window
The most tokens a model can read in one request.
AI gateway
The one place every model request goes through; here, LiteLLM.
alias
A friendly model name (fast) that the gateway maps to a real model.
virtual key
In a company gateway: a scoped, budgeted, revocable key for one app.
spend cap
A limit checked before each call; DocuMind's is max_spend_usd.
finish_reason
stop means the answer finished; length means it was cut off.
mock mode
Canned replies, for free practice and offline tests.
