SECTION 1

What an LLM call is

Explain like I'm 10

An LLM is a super-autocomplete. It reads your words as small pieces called tokens and guesses the next piece, then the next, until the answer is done. It forgets everything the moment it finishes.

Every LLM feature, however clever it looks, is one request: a list of messages goes in, one message comes out. The system message sets the rules. The user message carries the task, such as "summarize this invoice". The reply comes back with a token count and a finish_reason that says whether the model finished or was cut off.

Lesson L01 makes this call the "old way": straight to Anthropic, with the vendor key inside the program. Notice what's missing when you run it: there's no cost figure, no limit, and the code works with only one vendor.

SECTION 2

Why a gateway

Explain like I'm 10

A universal TV remote. One remote works every brand of TV, and only the remote knows the passwords. You press "fast" or "smart"; the remote decides which TV to switch on.

Picture three teams each calling vendors directly. Each team holds vendor keys, nobody sees total spend, and if a key leaks you hunt for it across every codebase. An AI gateway is one service that every app calls instead. DocuMind uses LiteLLM, an open-source gateway that speaks the OpenAI-compatible API format that most tools already understand.

ConcernDirect to vendorThrough the gateway
Vendor keysIn every appOnly in the gateway
Switching vendorCode change in every appEdit one alias in config
Spend controlA bill at month endBudget per key, enforced before the call
Leaked keyRotate the vendor key everywhereRevoke one virtual key
Cost per callNot visibleReturned with every answer
Retries, fallbacksRewritten in each appConfigured once (Module 04)
At enterprise scale

In a bank, the gateway is a shared platform service, and these are the questions to ask of it:

  • Secrets: vendor keys live in a secrets manager (for example HashiCorp Vault or AWS Secrets Manager), are injected at deploy, and rotate without any app noticing.
  • Identity: apps authenticate with SSO or service identities; there is one virtual key per app per environment, never a personal key in production.
  • Chargeback: spend per key and per team feeds finance; budgets and requests-per-minute limits are set per team.
  • Policy: an approved-model list per data classification, data-residency and retention terms per vendor, and an audit log of every call.
  • Resilience: several gateway replicas behind a load balancer, sharing Postgres and Redis. The gateway is now on the critical path, so it needs an SLO.
SECTION 3

Meet the gateway

The gateway's behaviour lives in one file, gateway/config.yaml. Its heart is the alias table: the names apps may ask for, and the real model behind each one.

Alias the app usesReal model$ / 1M input$ / 1M output
fast → fast-anthropicClaude Haiku 5.50.100.50
smart → smart-anthropicClaude Sonnet 5.52.0010.00
fast-openaiGPT-6 Luna0.100.50
smart-openaiGPT-6.1 Sol2.0010.00

Prices are from LiteLLM's built-in price list as of November 2026. Vendors change them, and the config file notes when they were last checked.

# gateway/config.yaml (excerpt)
model_list:
  - model_name: fast-anthropic              # the alias
    litellm_params:
      model: anthropic/claude-haiku-5-5     # the real model
      api_key: os.environ/ANTHROPIC_API_KEY # read from the gateway's environment
router_settings:
  model_group_alias: {fast: fast-anthropic, smart: smart-anthropic}
general_settings:
  master_key: os.environ/LITELLM_MASTER_KEY
  database_url: os.environ/DATABASE_URL     # where virtual keys and spend live

SECTION 4

Virtual keys

Explain like I'm 10

The master key is the head teacher's key ring. A virtual key is a hall pass: it opens only certain doors, runs out after a set amount, and the head teacher can cancel it at any time.

You are now the platform admin. With the master key you issue DocuMind its own virtual key. It may use only the listed aliases, may spend $2 every 30 days, and can be revoked instantly. The gateway records the key and its spend in Postgres. DocuMind stores this key as DOCUMIND_API_KEY and never sees a vendor key.

SECTION 6

Tokens, cost and knobs

Tokens are the unit of cost. English text averages about four characters per token. Output tokens cost about five times as much as input tokens, so long answers are the expensive part. Current models also think before answering, and thinking tokens are billed as output and count toward max_output_tokens.

A worked example

Summarize INV-1001Tokensfast (Haiku 5.5)smart (Sonnet 5.5)
Input: prompt + invoice≈ 420$0.000042$0.000840
Output: thinking + summary≈ 300$0.000150$0.003000
One invoice$0.00019$0.0038
10,000 invoices / month$1.92$38.40

The same job costs 20 times more on the smart model. Choosing the right model per task is model routing, the subject of Module 04.

The same question, different answers

The model picks each next token with some randomness, so the same prompt can give different wording on each run. Older tutorials set temperature=0 to reduce this. Current Claude models no longer accept temperature, and L06 shows the gateway rejecting it. You get consistency from clear prompts and structured output (Module 02), and you prove it with evals (Module 09), not with a knob.

SECTION 7

The model has no memory

Tell the model a fact, then ask about it in a new request: it has no idea. Chat apps seem to remember only because they resend the whole conversation each turn. Memory is therefore paid for in input tokens on every message, and a long chat eventually overflows the context window, the most text a model can read at once.

Deciding what to send, and what to leave out, is context engineering (Module 08).

CHECKPOINT

Can you explain it?

Answer each question out loud before opening it. The same quiz is in the module README.

A chat app "remembers" earlier messages. How, if the model is stateless?

The app resends the whole conversation with every request, so memory costs input tokens on every turn.

Name three things the gateway gives you that direct vendor calls don't.

Vendor keys kept out of apps; vendor swaps through aliases; budgets enforced before the call; instant revocation; cost and latency per call; central retries. Any three.

Master key vs virtual key?

The master key is the admin's root key and issues or revokes keys. A virtual key belongs to one app: it is scoped to certain aliases, has a budget, and can be revoked on its own.

The summary looks complete, but finish_reason is "length". What now?

The model hit the output limit, and thinking tokens count toward it. Raise max_output_tokens or ask for a shorter answer, and always check finish_reason.

A team wants to cut cost by 20x on 10,000 invoices a month. What is your first question?

Does the fast model's quality hold for this task? Answering that needs evals, not gut feel. Routing (Module 04) and evals (Module 09) turn the question into a measured decision.

Glossary

token
A small piece of text (about four characters) that the model reads and writes; the unit of cost.
context window
The most tokens a model can read in one request.
AI gateway
One service that all apps call instead of vendors; here, LiteLLM.
alias
A friendly model name (fast) that the gateway maps to a real model.
master key
The gateway admin key, used only to issue and revoke keys.
virtual key
A scoped, budgeted, revocable key for one app.
finish_reason
stop means the answer finished; length means it was cut off.
mock mode
The gateway returns canned replies, for free practice.
