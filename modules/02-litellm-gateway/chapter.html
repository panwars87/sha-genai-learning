SECTION 1

Why a gateway

Explain like I'm 10

A universal TV remote. One remote works every brand of TV, and only the remote knows the passwords. You press "fast" or "smart"; the remote picks the TV.

Picture three teams each calling vendors directly. Each team holds vendor keys, nobody sees total spend, a vendor outage takes every app down, and if a key leaks you hunt for it across every codebase. An AI gateway is the one door every model request goes through.

ConcernDirect to vendorThrough the gateway
Model namesScattered through codeAliases like fast, in one config file
Switching vendorCode change everywhereOne line of config
A vendor is downThe app is downFallback to another vendor
Cost per callA bill at month endOn every answer
Spend controlHopeA cap, checked before each call
Approved modelsAnything goesOnly the listed aliases work

The script searches this repo for vendor model IDs. They all live in documind/settings.yaml. The app's feature code has none; only the "before" lesson scripts from Module 0 do, on purpose.

SECTION 2

Aliases, shortcuts and fallbacks

DocuMind's gateway is LiteLLM's Router, configured entirely from one block of settings.yaml:

# documind/settings.yaml (excerpt)
gateway:
  aliases:                                       # a name for each real model
    fast-anthropic: anthropic/claude-haiku-5-5
    smart-anthropic: anthropic/claude-sonnet-5-5
    fast-openai: openai/gpt-6-luna
    smart-openai: openai/gpt-6.1-sol
    local: ollama_chat/llama3.2                  # optional, free, on your Mac
  shortcuts:                                     # what feature code asks for
    fast: fast-anthropic
    smart: smart-anthropic
  fallbacks:                                     # if this fails, try these
    fast-anthropic: [fast-openai]
  num_retries: 1
  max_spend_usd: 1.00

SECTION 3

One client, three vendors

The script runs Module 1's unchanged extraction on Anthropic, OpenAI and a local model. Only the alias string differs. LiteLLM translates one request format, including the structured-output schema, into each vendor's own API.

The local model is optional. Ollama runs open models on your Mac: free, private, offline. If it isn't running, the script skips it with a hint. Small local models are usually less accurate on awkward documents; balancing cost, quality and speed per document is model routing (Module 4).

SECTION 4

Fallbacks: something always fails

Explain like I'm 10

If one shop is shut, you walk to the next one and still come home with milk.

Vendors have outages, rate limits and bad days. The gateway handles failure in two layers, so feature code never has to:

  • Retries (num_retries): try the same model again, for blips like a timeout.
  • Fallbacks: try a different alias, usually another vendor, when the first keeps failing.

The script rehearses a failure (LiteLLM pretends the primary failed), then causes a real one by pointing fast-anthropic at a model that doesn't exist. The answer still arrives. The stats line says OpenAI wrote it, and DocuMind logs a WARNING. A silent fallback hides an outage, so always log it.

SECTION 5

Spend caps and approved models

Explain like I'm 10

Pocket money. When it's spent, it's spent, however nicely you ask.

Two guarantees, both checked before any vendor is called. A spend tracker adds up each call's cost and refuses the next call once max_spend_usd is reached. And only names in settings.yaml work: asking for gpt-4 is refused, which is how a company enforces an approved-model list.

In a company, both live on a virtual key: the shared gateway's admin holds the master key and issues each app its own key, with allowed models and a budget. A key can be revoked in seconds without touching any other app.

SECTION 6

Switch vendor by config only

The payoff. The script runs the unchanged DocuMind command line twice: once as configured, once with one environment variable, DOCUMIND_GATEWAY__SHORTCUTS__FAST=fast-openai. The second run is answered by OpenAI. No Python changed; you could make it permanent by editing one line of settings.yaml.

This is the whole path of a DocuMind request. The vendor key is used in exactly one place: inside LiteLLM, inside llm.py.

SECTION 7

Library or server?

In this course LiteLLM runs as a library inside DocuMind: nothing to install or keep running, and the concepts are fully visible in documind/llm.py. In a company the same LiteLLM usually runs as a shared proxy server that every team calls with an OpenAI-compatible API. The ideas are identical; only where it runs changes.

At enterprise scale
  • Secrets: vendor keys live in a secrets manager (HashiCorp Vault, AWS Secrets Manager), are injected at deploy and rotate without any app noticing.
  • Identity: apps authenticate with SSO or service identities and get a virtual key per environment.
  • Chargeback: spend per key and per team feeds finance; budgets and rate limits are set per team.
  • Policy: approved models per data classification, data residency and retention terms per vendor, and an audit log of every call.
  • Resilience: several gateway replicas behind a load balancer. The gateway is now on the critical path for every AI feature, so it needs an SLO of its own.

CHECKPOINT

Can you explain it?

Name three things a gateway gives you that direct vendor calls don't.

Aliases (switch vendor by config), fallbacks, cost per call, spend caps, an approved-model list, one place for keys. Any three.

What's the difference between an alias and a shortcut here?

An alias names a real model (fast-openai). A shortcut names a job (fast) and points at an alias, so ops can repoint it without touching code.

Retry or fallback: which handles a 2-second blip, and which a 2-hour outage?

A retry handles the blip (same model again). A fallback handles the outage (a different vendor).

Why log a warning when a fallback answers?

Otherwise an outage, a cost change or a quality drop is invisible. Observability starts in Module 3.

In a company, how is a spend cap usually enforced?

The shared gateway gives each app a virtual key with a budget and allowed models, and checks it before calling the vendor.

Glossary

AI gateway
The one place every model request goes through; here, LiteLLM's Router.
alias
A friendly name for a real model, defined in settings.yaml.
fallback
Another alias to try when the first one fails.
retry
Trying the same model again after a transient error.
spend cap
A budget checked before each call; DocuMind's is max_spend_usd.
virtual key
In a company gateway: a scoped, budgeted, revocable key for one app.
Ollama
An optional app that runs open models locally on your Mac.
